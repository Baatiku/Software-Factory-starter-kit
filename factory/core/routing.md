# Work routing and proportional depth
Identify the **requested outcome** before selecting a method, file format, tool, provider or skill.
1. Inspect fresh existing deliverables and instructions. New work, continuation, correction and diagnosis are different routes.
2. Choose applicable packs; combine them only where the outcome actually crosses domains.
3. Record any irreversible decision, real external action, meaningful ambiguity and owner authorization. Use safe reversible defaults otherwise.
4. Quick: complete directly, with no heavyweight scaffold. Standard: compact outcome, acceptance, evidence and continuation. High assurance: add explicit risk, recovery, approval and audit checks.
5. For an AI coding project use software plus only relevant publishing/automation/infrastructure. For an editorial article do not require Git, UI screens or a deployment.
6. Keep confidence explicit: observation, cited research, tested fact, assumption and unknown are distinct. Do not promote chat memory or stale docs above the live target.
7. Judge work by achieved outcomes, not number of agents, generated documents, lines of code or PRs.
