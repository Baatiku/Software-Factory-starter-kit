# Project migration to Universal Work Factory 1.0.1

The upstream repository now maintains only the universal router, specialist packs and associated scripts. Earlier project-local copies are independent and **will not be silently deleted or overwritten**.

For an existing project using an older scaffold, inspect its actual files and owner decisions; create a temporary test checkout. Run `python scripts/factory.py init --repo ./the-project --idea "current project outcome" --profile software` only after checking any preexisting project instructions; the command preserves such files. Review new `docs/WORK-OUTCOME.md`, verify that unique project-specific details are retained, then remove obsolete local project-specific files only with project authorization. The universal CLI can `upgrade` only an initialized project with its own `.factory/work-manifest.json`. Use `upgrade` without `--apply` for dry-run first; customized files always remain untouched.

For new work, the canonical factory contains `factory/core/`, `factory/packs/`, `factory/templates/`, `scripts/factory.py`, `factory/tools/github_claims.py` and only `.agents/skills/work-factory` plus specialized skill entries.

`check --gate structure`, `delivery`, `release` are structural checks only; real production, research and publication evidence requires separate external execution. Portable ZIPs generated by `scripts/package_work_factory.py` are not automatically installed in ChatGPT, Codex or Claude.

Removing obsolete files from the current Git tree preserves the repository's original Git history. Do not force-rewrite history, reset unrelated repositories, or delete customer project source as a side effect of upgrading toolkit instructions.
